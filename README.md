# Pakia Pakia!

A daily grocery-bagging logic puzzle for Reddit, built on Devvit Web.

## The name

*Pakia* (say "pah-KEE-ah") is Swahili for "pack" or "load", as in loading goods. Swahili often doubles a word for emphasis, so *Pakia Pakia!* is the shout of someone packing fast: "pack it, pack it!". It is also what the stamp says when your bag is done.

Every day a new receipt drops. Pack every item into a 5 by 5 paper bag without breaking the house rules. Then vote on the receipts other players wrote: the most voted one becomes tomorrow's puzzle, credited to its author.

## How to play

- Tap an item on the receipt, then tap the bag. Or drag it in.
- Turn the item in your hand with Rotate, or tap it again.
- Tap an item already in the bag to pick it back up, or drag it out of the bag. Undo and Empty bag are always there.
- The bag is solved when every item is packed and no rule is broken.

### House rules

| Rule | Icon | Meaning |
| --- | --- | --- |
| Floor | weight | Heavy items must sit on the bottom row of the bag. |
| On top | glass | Fragile items need nothing stacked above them, in any row. |
| Apart | snowflake, flame | Cold and hot items cannot share a side. |
| Upright | arrow | Upright items cannot be turned on their side. |

A broken rule lights up its chip and marks the items involved, with one short sentence saying what went wrong.

### Special request

Every receipt also carries one special request from its customer, handwritten under the receipt title. It always names items that appear once on the receipt:

| Request | Meaning |
| --- | --- |
| Top row | The item touches the top of the bag. |
| Off the floor | The item does not touch the floor. |
| In the middle | The item covers the center square. |
| Away from | Two items do not share a side. |
| Next to | Two items share a side. |
| Above | The first item sits entirely higher than the second. |

A request is only accepted if it removes some valid bags, so it always changes how you pack. Breaking it turns the line red, like a house rule.

Desktop shortcuts: `R` rotates, `Z` undoes, `Escape` drops the item in hand.

## Customer of the Day

This is the community loop that makes Pakia Pakia! a Reddit game rather than a puzzle that happens to live on Reddit.

1. Solve today's bag.
2. On the result card, vote for one of the receipts other players wrote (top 3 shown, never your own).
3. Write your own receipt: a name, 6 to 10 groceries, a special request and an optional note (60 characters). The solver checks it live in the editor, so only packable receipts whose request really matters can be sent.
4. At 00:00 UTC the scheduler elects the most voted receipt. It becomes the new daily post, its title names the author, and the author gets a "Customer of the Day" flair.
5. When nobody voted, a verified house receipt is used instead, so there is always a puzzle.

Other community touches:

- Streak flair (`N-day bagger`) from a 2-day streak.
- "Share my time" posts a comment as the player, with time and moves.
- Hivemind: the most common item in each cell, across everyone who solved today.
- Same bag: how many players packed exactly the same bag as you.
- Top baggers: today's leaderboard, ranked by time, then moves.

## Puzzles

- `src/shared/puzzles.ts` holds 101 house receipts, from 2026-11-20 to 2027-02-28. It is generated by `npm run generate:puzzles`; do not edit it by hand.
- Each receipt is checked by an exact solver (`src/shared/solver.ts`: bitmask backtracking, most constrained item first, identical items deduplicated).
- Every house receipt has a special request, picked by the generator among the requests that remove solutions and keep the day's difficulty. Consecutive days avoid repeating the same kind of request.
- Difficulty measures how much planning a bag asks for, request included (`src/shared/difficulty.ts`). A simulated careless player packs the biggest items first and drops each one on a random spot that breaks no rule yet, never undoing. The share of 1 000 such games it wins is the naive win rate: hard under 4%, medium under 15%, easy above. Counting valid bags alone was misleading: two receipts with the same count can feel very different.
- House receipts aim inside each band: easy days at 18 to 45% (still one or two real decisions), medium at 5 to 13%, hard at 1 to 3,5% (demanding but fair). Community receipts above 60% are refused because the bag packs itself.
- The week follows a curve: Monday and Tuesday easy, Wednesday, Thursday and Sunday medium, Friday and Saturday hard.
- The judging window, Dec 9 to 16, 2026, has hand-picked holiday themes.
- `npm run analyze:puzzles` prints the rating of every house receipt.
- Days are keyed in UTC. Day #1 is 2026-11-20.
- `npm test` checks that every house receipt is solvable with its request and rated as declared, that the request removes solutions, that no bag packs itself, and that every day of the judging window has a puzzle.

## Architecture

```
src/
  shared/    rules, solver, validator, dates, puzzle pool, receipt checks (used by client, server and tests)
  server/    Hono routes on Devvit Web: API, moderator menus, form, install trigger, daily scheduler
  client/    splash card (vanilla) and game (React 19, Tailwind 4), item art, icons, fonts, sounds
tools/local/ in-memory mocks of Redis and the Reddit API for the local playground
scripts/     puzzle generator
tests/       node:test suite for the shared logic
```

- Entry points (`devvit.json`): `default` is the inline splash card in the feed, `game` is the expanded game view.
- The server validates every solve with the same rule engine as the client, and clamps the reported time against server-side timestamps.
- Storage is Devvit Redis only. There are no external network calls: fonts and icons are bundled.
- Moderator menu: "Pakia Pakia!: post today's bag" and "Pakia Pakia!: review community receipts".
- Scheduler: `daily-post` runs at 00:00 UTC, elects the receipt and creates the post.

## Run it locally (no Reddit account needed)

Requirements: Node 24 or later (Node 22 works for the local playground).

```bash
npm install
```

```bash
npm run dev:local
```

Then open http://localhost:5173. The real client and the real API routes run against in-memory mocks. A small Dev menu at the top of the page lets you:

- switch player (`local_bagger`, `alice`, `bob`, `carol`, `guest`) to test votes and leaderboards;
- open any day, or the splash card;
- seed 3 community receipts with votes, then run the midnight election;
- forget local progress, or reset all server data.

Server-side effects (comments, flair, posts) are printed in the terminal.

## Run it on Reddit

```bash
npm run login
```

```bash
npm run dev
```

`npm run dev` runs `devvit playtest`: it builds, uploads a development version and installs it on your test subreddit. Then use the subreddit menu "Pakia Pakia!: post today's bag".

`npm run deploy` type-checks, lints, tests and uploads.
